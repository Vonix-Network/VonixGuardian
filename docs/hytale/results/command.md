## Permission matrix

Hytale checks the generated node before `execute`, via `CommandSender.hasPermission`. For a plugin-owned tree that is `{base}.command.guardian` and `{base}.command.guardian.<sub>`, and the parent walk also requires `{base}.command.guardian` unless `permissionGroups` is set. This cell does not call `requirePermission`, so that generated chain stays in place. `ConsoleSender.hasPermission` is always true, so the generated chain does not stop the console.

Inside `execute`, a player must pass `PlayerDirectory.hasPermission` for both `PluginBase.getBasePermission()` and the Vonix node below. A null directory, a thrown check, a null uuid, a missing owner, or a blank base permission is a refusal. Read-only console commands skip that check. Mutating commands refuse every non-player.

`vonixguardian.command.viewothers` is not a subcommand. On lookup, rollback, restore, and purge, a player without it is scoped to self when `u:` is empty, and an explicit other user or sentinel is rejected. A failed viewothers check refuses the query. Undo uses only that player's own stack.

Rollback and restore report `MutationOutcomeFormatter` lines. `FAILED` is the error color, `SUCCESS` is the success color, and `PARTIAL`, `COMPENSATED`, and `REPAIR_REQUIRED` are the warning color. A silent success that is not a preview sends no line. `#count` prints the count line from `plan()` only. Undo history is pushed only when `mutatedWorld()` is true. Undo pops only when the inverse `isSuccess()` or `mutatedWorld()`. An `execute` exception does not claim the world is unchanged and does not push or pop. Purge reports `deletedCount` and the age floor, and never calls the outcome a blanket success. Reload reports hot-swapped, requires-restart, and error counts; a non-empty error list says the live config is unchanged.
